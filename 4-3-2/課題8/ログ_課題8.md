# 課題8: Discord の Webhook でチャンネルに通知する

作業日: 2026年10月13日

教材の項目名は「6. Discord」だった。このフォルダの課題6は YouTube なので、Discord は課題8として置いた。

## やったこと

Discord の Webhook で、特定のチャンネルに通知を1件送るスクリプトを作成した。

- 本体: `4-3-2/課題8/discord_notify.py`
- API: `POST https://discord.com/api/webhooks/{id}/{token}?wait=true`
- 認証: チャンネルに結び付いたウェブフックURL
- 追加ライブラリはなし。標準ライブラリの `urllib` だけで通信する

課題文は「ボットを作成し、自動通知を送る」だった。ヒントは「webhookを使うと簡単」なので、常駐するボットは作っていない。Webhook がそのチャンネル専用の送信口になり、届いたメッセージは Webhook の名前で表示される。

## 使い方

```bash
python3 discord_notify.py "メッセージ"
```

今回の実行は次のとおり。

```bash
python3 discord_notify.py "課題8から通知しました"
```

URL はリポジトリの外に置く。権限は `600`。

```text
~/.config/discord/webhook.env
```

中身は次の1行。

```text
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
```

## 設計で判断したこと

**1. 常駐ボットではなく Webhook にした**

ボットを作ってサーバーに常駐させると、アプリケーションの作成、トークン、招待、接続の維持が必要になる。通知を1件届けるだけなら、チャンネルの設定で Webhook を1つ作れば足りる。URL がそのチャンネルに結び付いているので、スクリプト側でチャンネル名は指定しない。

**2. ボットトークンでは送らない**

受け付けるのは `https://discord.com/api/webhooks/` で始まる URL だけにした。ボットトークンやサーバーIDを入れても通知できない。URL 自体は画面に出さない。

**3. 返事を待ってメッセージIDを取る**

Webhook は、待たずに送ると中身の無い成功（状態コード 204）を返す。`wait=true` を付けると、作成されたメッセージが返る。届いたことの確認に、チャンネルIDとメッセージIDを表示する。

**4. User-Agent を付ける**

Discord は、User-Agent の無いリクエストを拒むことがある。課題用だと分かる短い名前を付けている。

## 事前準備

Discord で通知先のチャンネルを開き、チャンネル名の横の歯車から **連携サービス** → **ウェブフック** → **新しいウェブフック** を作った。コピーした URL を `~/.config/discord/webhook.env` に保存した。チャットや Git には貼っていない。

## 実行結果

通知に成功した。

```text
【課題8】Discord へ通知を送る
本文 : 課題8から通知しました
通知しました
チャンネルID : 1494842275400777740
メッセージID : 1559378536895352843
```

同じコマンドをもう一度実行すると、同じチャンネルにもう1件届く。提出用の画面は、その再実行で撮る。届いたことの確認は、API で履歴を読んだのではなく、Discord のチャンネルを開いて見る。

## この API でできること

Discord の画面を開かずに、Webhook を作ったチャンネルへ1件通知できる。人がメッセージを書いて送る作業の置き換えである。

他のチャンネルを読むこと、サーバーの管理、常時オンラインのボットとして会話することは、この Webhook の範囲ではない。外の処理が終わったあと、同じチャンネルに結果を1件返す、という通知口に使える。
