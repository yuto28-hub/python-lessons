# 課題4: Zoom API で会議を作成する

作業日: 2026年10月7日

## やったこと

Zoom API で会議を1つ作り、会議ID・パスワード・参加リンクを表示するスクリプトを作成した。

- 本体: `4-3-2/課題4/zoom_create.py`
- 認証: Server-to-Server OAuth（ブラウザの許可は不要。Account ID / Client ID / Client Secret でトークンを取る）
- 作成: `POST https://api.zoom.us/v2/users/{メールアドレス}/meetings`
- 追加ライブラリはなし。標準ライブラリの `urllib` だけで通信する

## 使い方

```bash
python3 zoom_create.py           # 既定の議題で会議を作る
python3 zoom_create.py "朝会"     # 議題を指定して会議を作る
```

鍵はリポジトリの外に置く。

```text
~/.config/zoom/credentials.env
```

中身は次の4行。権限は `600`（自分だけが読める）。

```text
ZOOM_ACCOUNT_ID=...
ZOOM_CLIENT_ID=...
ZOOM_CLIENT_SECRET=...
ZOOM_USER_EMAIL=...
```

## 設計で判断したこと

**1. 認証は Server-to-Server OAuth にした**

会議を作るたびにブラウザで許可をもらう必要がない。Zoom Marketplace でアプリを1回作り、Activate すれば、あとは鍵3つで1時間有効なアクセストークンを取れる。トークンの更新用（refresh token）は無いので、切れたら同じ手順で取り直す。

**2. 主催者に `me` を使わなかった**

Server-to-Server では `POST /users/me/meetings` が使えない。主催者のメールアドレスをパスに入れる。だから `ZOOM_USER_EMAIL` が必要になる。

**3. 主催者用リンクは出さない**

API の返事には `join_url`（参加者用）と `start_url`（主催者用）の両方がある。`start_url` には主催者として入るための秘密が含まれるので、表示するのは課題が求めている3つだけにした。

- 会議ID（`id`）
- パスワード（`password`）
- 参加リンク（`join_url`）

パスワードはこちらで決めず、Zoom のアカウント設定に従って発行させる。

**4. 会議の種類は「今すぐ入れる会議」**

`type: 1` にした。開始日時を決めなくてよい。待合室はオン、ホストより先の入室はオフ。

## 事前準備でつまずいたところ

Marketplace を開いた最初の画面は、公開アプリの一覧だった。アプリを作る場所は、ログイン後に左下の **Developers** から入る **Created Apps** である。そこで Server-to-Server OAuth のアプリ「Yuto」を作った。

| 画面 | やったこと |
|------|-----------|
| Feature | Event Subscriptions はオフのまま。会議作成には不要 |
| Scopes | 「Create a meeting for a user」（admin）を追加。ウェビナー用の項目は付けない |
| Activation | 最初は有効化できなかった。Information の開発者名、連絡メール、会社名が空だった |
| Activate | 3項目を入れてから有効化した |

有効化前に実行すると、鍵が正しくても次のエラーになる。

```text
400 invalid_client
The app has been disabled by the developer
```

これは文字列の間違いではなく、アプリがまだ Activate されていないという意味だった。

## この API でできること

Zoom の画面を開かずに会議を作り、返ってきた ID・パスワード・リンクを次の処理へ渡せる。人が「新しい会議」を押す作業の置き換えである。

たとえば、会議を作った直後にそのリンクをメールで送る、申し込みがあった件数だけ会議を作る、といったつなぎ方になる。会議中のミュートや画面共有は、この API の範囲ではない。
