# 課題9: LINE Messaging API でメッセージを送る

作業日: 2026年11月1日

## やったこと

LINE Messaging API で、公式アカウントからテキストを1件送るスクリプトを作成した。

- 本体: `4-3-2/課題9/line_send.py`
- API: `POST https://api.line.me/v2/bot/message/push`
- 認証: チャネルアクセストークン（長期）
- 送り先: 自分のユーザーID（`U` で始まる33文字）
- 追加ライブラリはなし。標準ライブラリの `urllib` だけで通信する

新しい公式アカウントは作っていない。以前作ってあった **領収書bot**（`@198zfmev`、コミュニケーションプラン）をそのまま使った。Messaging API はすでに「利用中」だった。

## 使い方

```bash
python3 line_send.py "メッセージ"
```

今回の実行は次のとおり。

```bash
python3 line_send.py "課題9から送りました"
```

トークンとユーザーIDはリポジトリの外に置く。権限は `600`。

```text
~/.config/line/token.env
```

中身は次の2行。

```text
LINE_CHANNEL_ACCESS_TOKEN=長期のチャネルアクセストークン
LINE_USER_ID=Uで始まるユーザーID
```

## 設計で判断したこと

**1. 返事用のサーバーは作らなかった**

ユーザーからのメッセージに返す方式は、Webhook を受け取る公開サーバーが要る。課題は「メッセージを送る」だけなので、こちらから1件送るプッシュにした。Webhook URL は空のままでよい。

**2. 使う鍵はチャネルアクセストークン（長期）だけにした**

LINE Official Account Manager の Messaging API 画面には Channel ID と Channel secret も出る。送信に使うのは、LINE Developers コンソールの「Messaging API設定」で発行する長いトークンである。Channel secret や、公開用の `@198zfmev` では送れない。

**3. 送り先は「あなたのユーザーID」にした**

プッシュは、相手のユーザーIDが必要である。開発者自身の ID は、同じチャネルの「チャネル基本設定」に出る。友だち追加済みの自分に送れば、スマホの LINE で届いたことを確認できる。

**4. トークンは画面に出さない**

成功時に表示するのは本文とユーザーIDだけにした。トークンの欄にユーザーIDを入れた場合と、ユーザーIDの形が違う場合は、送る前に止める。

## 事前準備でつまずいたところ

公式アカウントの作成場所は、LINE Developers コンソールではない。2024年9月から、Messaging API のチャネルはコンソールから直接作れなくなった。公式アカウントを作り、LINE Official Account Manager で Messaging API を有効にする。

領収書bot の Messaging API 画面には、以前のボット用の Webhook URL が入っていた。今回の送信には使わないので、**保存** は押さず、そのままにした。

チャネルアクセストークン（長期）は発行済みだった。**再発行** は押していない。再発行すると、今のトークンは無効になる。

最初の保存では `保存しました` と出たが、ファイルの中身は空だった。貼り付けは画面に表示されないので、Enter だけが押されていた。同じコマンドをもう一度実行し、トークンとユーザーIDを貼り付けてから Enter した。確認した長さは、トークン 382 文字、ユーザーID 33 文字だった。

## 実行結果

送信に成功した。

```text
【課題9】LINE へメッセージを送る
本文 : 課題9から送りました
送信しました
ユーザーID : Ucdcc7f2fb02ebf5f3aeeac56c3349132
```

届いたことの確認は、API の成功だけでは完了しない。スマホの LINE で **領収書bot** のトークを開き、「課題9から送りました」が見えることを確認する。友だち追加していない相手には届かない。

## この API でできること

LINE の画面を開かずに、公式アカウントから指定した友だちにテキストを1件送れる。人がトークを開いて書く作業の置き換えである。

友だち以外への送信、画像やボタン付きのメッセージ、相手からの返事を受けることは、このスクリプトの範囲ではない。外の処理が終わったあと、同じ公式アカウントから結果を1件知らせる、という通知口に使える。
